# Supprimer un service (HRT-85)

Capacité `service-delete` annoncée par [`GET /hello`](./hello.md). Deux routes, toutes deux au niveau « gérer les services » (`Access::Services`, quel que soit le rôle, `BR-DEL-001`). Règles `BR-DEL-001` à `006`, `008`, `011` à `019`, `021`, `022`, `025`, `028` à `031`, décisions ADR-0045 (opérations), ADR-0046 (fichiers), ADR-0039 (moteur). Types : `hearth_proto::api::service_delete`.

**Par défaut rien n'est perdu** : sans case cochée, seuls le conteneur, la description (nom, variables, ports, commande et leurs valeurs scellées) et les journaux du moteur partent ; les dossiers de données, l'image, les volumes du moteur et les sauvegardes restent. Les données ne partent que sur demande explicite, et alors le nom du service doit être retapé.

## `GET /api/v1/services/{key}/delete-preview`

De quoi bâtir la fenêtre « Supprimer {nom} ? ». Une consultation : rien n'est écrit, rien n'est journalisé (seul un refus faute du droit l'est).

- **Réponse `200`** (`DeletePreview`) : `name`, `image` (`dépôt:version`, elle reste sur le serveur), `running` + `stop_grace_s` (le service sera arrêté d'abord, `BR-DEL-013`), `container_missing` (le conteneur n'existe plus, le service reste supprimable, `BR-DEL-018`), `folders[]`, `server_folders[]`, `volumes`, `measured_in_time`, `backups` (toujours `0` tant que l'agent n'a pas de sauvegardes, HRT-97 : la case « sauvegardes » n'est pas proposée).
- **`folders[]`** (`FolderPreview`) : les dossiers gérés par Hearth, `path` (réel, sur le serveur : ce champ ne sort que vers les comptes qui ont le droit), `bytes` (taille sur le disque), `items`, `partial` (mesure coupée : « plus de {taille} »), `unmeasured`, `fate` : `erasable` (effacé si la case est cochée), `kept_shared` (un autre conteneur l'utilise : `shared_with[]` les noms des services, `shared_with_unmanaged` un conteneur créé hors de Hearth, sans nom, `BR-DEL-008`), `kept_unverifiable` (un autre conteneur a des montages que l'agent ne lit pas : conservé par prudence), `kept_outside_root` (son nom ne se juge pas comme un dossier sûr de la racine de données). Un dossier du serveur monté dans le service est dans `server_folders[]` et n'est jamais effacé (`BR-DEL-006`).
- **Mesure bornée à 10 secondes pour tous les dossiers ensemble** (`BR-DEL-009`), une mesure à la fois pour tout l'agent, sans rien lire ni franchir de point de montage. `measured_in_time: false` : au moins un dossier est « plus de {taille} » ou n'a pas été mesuré.
- **Erreurs** : `403` sans le droit ; `404 SERVICE_NOT_FOUND` (inconnu, clé mal formée, ou que Hearth ne connaît plus) ; `409 SERVICE_ADOPTED` (service adopté ou créé hors de Hearth, `BR-DEL-002`) ; `409 ENGINE_UNAVAILABLE` (moteur pas « Prêt », `BR-DEL-022`).

## `DELETE /api/v1/services/{key}` (acte `ServiceDelete` `0x14`)

Un acte d'administration du socle, **jamais couvert par l'élévation** (le mot de passe à chaque fois, même sans case cochée, `BR-DEL-012`). Cible signée : la clé du service. Paramètres signés : `data:0|1`, `backups:0|1`. Le nom retapé n'est pas signé.

- **Corps** (`DeleteRequest`, avec le membre `reauth` à côté) : `erase_data` (défaut `false`), `erase_backups` (défaut `false`, refusé s'il est coché : l'agent n'a pas de sauvegardes), `confirm_name` (exigé si une case est cochée, égal au nom du service casse comprise, `BR-DEL-011`).
- **Réponse `202`** (`DeleteAccepted`) : `{ "operation_id": "…" }`. L'issue se lit dans l'opération (`GET /operations/services/{id}`, le message `operation` du flux, [opérations de service](./service-ops.md)).
- **Déroulé** (`BR-DEL-014`, étapes de l'opération) : `stop` (si le service tourne : arrêt voulu écrit avant l'ordre, arrêt propre avec le délai de grâce du service, coupure forcée dite dans le journal, `BR-DEL-013`) ; **`remove_container`, le point de non-retour** (jusque-là l'opération est annulable par `DELETE /operations/services/{id}` et ne laisse aucune trace ; le conteneur est supprimé SANS toucher à ses volumes et SANS force) ; `forget` (description et valeurs scellées, conteneurs consignés, arrêt voulu, suivi des phases d'un jeu) ; `erase` (seulement si `erase_data`, **après** le conteneur, jamais avant). Le nom du service est réservé pendant toute l'opération : un déploiement du même nom reçoit `409 NAME_BEING_DELETED` (`BR-DEL-019`).
- **L'effacement** (`BR-DEL-006` à `BR-DEL-008`, `BR-DEL-030`) : les seuls dossiers gérés par Hearth que personne d'autre n'utilise (rejugé juste avant d'effacer chacun), un à un, sans suivre un lien, sans franchir un montage, à faible priorité sur un fil dédié, avec `items_done` dans l'opération. La racine du service ne part que si elle est vide ensuite.
- **Issues** : `succeeded` ; `succeeded` avec la cause `data_not_erased` si des éléments n'ont pas pu être effacés (le service est supprimé, rien n'est rejoué, `BR-DEL-016`) ; `failed` (`engine_unavailable`, `timeout`, `engine_refused`) si l'arrêt ou la suppression du conteneur échoue : le service reste entier avec sa description et ses données (`BR-DEL-015`) ; `interrupted` si le moteur ne répond plus à l'ordre (résultat inconnu) ; `cancelled` si le compte annule avant le point de non-retour (le service est laissé arrêté).
- **Redémarrage de l'agent** (`BR-DEL-025`) : une suppression coupée au milieu d'une étape qui détruit est `needs_attention` (cause `intent_without_done`), le nom reste réservé, la seule décision offerte est `verified` (« j'ai vérifié ») ; elle n'est ni reprise, ni rejouée, ni défaite : le dossier a pu être réutilisé entre-temps.
- **Erreurs** : `403` sans le droit ; `404 SERVICE_NOT_FOUND` ; `409 SERVICE_ADOPTED` (« Hearth ne supprime pas les services créés hors de Hearth. Tu peux seulement ne plus le gérer. », refus journalisé avec la cause « service adopté », `BR-DEL-002`) ; `409 SERVICE_BUSY` (`details.by`, `details.kind`, `BR-DEL-021`) ; `409 SERVICE_NOT_DRIVABLE` (`details.state` : en pause, état non reconnu, déploiement en cours..., `BR-DEL-003`) ; `409 ENGINE_UNAVAILABLE` ; `422 VALIDATION_ERROR` (`details.field` : `confirm_name` si le nom retapé est faux, `erase_backups` si la case est cochée) ; `426` client trop ancien (confirmation absente).
- **Journal d'activité** (`BR-DEL-029`) : `service.delete`, cible « service {nom} » + mentions chiffrées (« , données effacées (n dossiers, taille) », « , arrêt forcé », « , données non effacées (n) »), résultat et cause de la liste fermée. Jamais un chemin, un nom de fichier, une variable ni une commande.
- **Code** : `entrypoint/http/service_delete.rs`, `application/delete.rs` (`ServiceDeletion::{preview, delete}`), `domain/ops/delete.rs`, `domain/services/delete.rs`, `application/ports/safe_fs.rs` (`erase_tree`, `remove_empty_service_root`), `application/ports/container_engine.rs` (`remove_keeping_volumes`).
